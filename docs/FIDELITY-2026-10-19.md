# Screen comparison and homepage SEO

Reference: https://noillirk.com/. Rechecked October 19, 2026. No subagents.

## Evidence and method

All **92 original modules/styles** in the pinned reference graph were fetched again and matched their recorded original SHA-256 values. The reference had not changed this graph since the preceding import. Game controllers, renderers, audio implementation and presentation CSS remain the authorized source; OpenNoillirk service/brand adaptations are recorded separately.

`scripts/fidelity-audit.mjs` drives both sites in separate browser contexts with the same viewport, date/timezone, questions and answers. Reference-only diagnostic hooks expose the same controller state used by our audit. Result-save and board APIs are supplied with equal test fixtures on both sites, so the comparison does not post test scores to the reference service. Third-party reference telemetry is blocked for this audit; its resulting integrity warning is intentionally excluded. Real application errors and missing resources remain failures. Our production database/challenge behavior is checked separately by the existing full acceptance and API audits.

Desktop 1440×864: homepage, active question, early reveal, reveal board, completed result, share dialog and downloaded PNG for both stages. Phone 390×844: both home and question screens. A second mixed run checks all five answer bands, passing, timeout, alternate moment cards and copy-link destinations. Screenshots and complete reports are in ignored `output/fidelity/` and `output/fidelity-mixed/`.

## Findings and changes

- Homepage/game geometry, answer reveal, camera/crowd behavior, result layout, share dialog, card composition and QR placement follow the reference components. No new functional game discrepancy was found in these comparisons.
- **Favicon difference fixed:** the earlier project-drawn version used a different background, spacing and corner treatment. The build now uses the authorized reference SVG and generates the PWA icons from that exact source.
- OpenNoillirk name/domain, ownership/contact/source links and own privacy terms intentionally differ. The longer brand word occupies more horizontal space than Noillirk. The visible homepage H1 continues to include the requested Noillirk game keyword.
- Homepage title, description, keywords and social metadata now emphasize Noillirk consistently in prerendered HTML and the client route head.
- A supplementary, user-expandable game guide is added below the existing homepage content. Its summary is visible, its complete text is server-rendered, and it is collapsed by default. It uses the reference reading-section behavior while gameplay is focused. The first game viewport retains its original geometry.

## SEO verification

English word tokens are counted case-insensitively from body text, excluding script/style contents. The keyword counts only the standalone word **Noillirk**, rather than counting the substring inside OpenNoillirk or inflating the metric with meta tags.

- Prerendered homepage: **4,191 words**, **134 keyword occurrences**, **3.197%**.
- Hydrated desktop and phone homepage: **4,184 words**, **133 occurrences**, **3.179%** in the audited initial state.
- New guide alone exceeds 1,500 words. H1/title/description/keywords include Noillirk.
- Normal user agents and Googlebot receive the same homepage HTML in the local audit. No crawler-only page or inaccessible keyword block is used.
- Native details/summary can be opened by pointer and closed with the keyboard. Browser checks verify a single guide instance, no console errors and invisibility of the reading section during focused gameplay.

The accessible accordion approach follows [Google's distinction between ordinary expandable content and hidden text abuse](https://developers.google.com/search/docs/essentials/spam-policies#hidden-text-and-link-abuse). The requested density is a content acceptance target, not a search-ranking guarantee.
